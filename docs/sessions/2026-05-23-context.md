## Origin and arc

Conversation opened with the operator asking what could be done for a
first vertical slice of Atlas — runnable through Playwright with
real databases and per-step screenshots. From there the work moved
through four distinct streams that ended up interleaving:

1. **Spec change: I20 + §11.** Operator stated a "vision" requirement
   — everything Atlas does for an end-user MUST ship as an intent or
   data change, never as a restart. Kernel changes are categories to
   extract, not the default. This landed as a new invariant + a
   normative retrospective process in `always-on.md`.

2. **First-feature slice — `tenant-admin-invites-user`.** The
   executable witness for I20. Scoped through the full slice
   workflow (spec-keeper, sdet, frontend-dev, module-dev). The §11
   retrospective loop fired **four times** during this slice;
   three retros closed, one is parked behind a platform-tenancy gap.

3. **`atlas doctor` substrate.** First slice of an
   operator-environment self-diagnosis framework. Shipped with two
   checks (`podman-machine`, `podman-compose-provider`) because
   running the BDD locally surfaced a Windows-specific compose-provider
   delegation issue that wasn't the named-pipe problem it initially
   appeared to be.

4. **Stryker `node:test` runner plugin.** Built from the operator's
   ask for higher-confidence behavior coverage. TDD-built against the
   Stryker `command` runner as oracle; parity verified end-to-end.

The TDD doctrine landed in root `CLAUDE.md` after the loop above
demonstrated its value — the Reconciliation Rule is the operator's
named directive for "when BDD fails while unit tests pass, the unit
tests are not actually wrapping the behavior, examine architecture."

**Three bugs the TDD loop surfaced + caught:**
1. Parent's `NODE_TEST_CONTEXT` / `NODE_TEST_WORKER_ID` env vars
   leaking into spawned children silently suppressed node:test
   discovery. Strip `NODE_TEST_*` from child env in the spawn.
2. Race between child-exit and readline-flush left tail TAP output
   un-parsed. Gate drain on both.
3. Missing `__STRYKER_ACTIVE_MUTANT__` env in the spawn meant
   instrumented mutants ran their original branch — everything
   survived. Set it from `options.activeMutant.id`.

## Calibration insights to carry forward

These showed up repeatedly enough to record permanently:

1. **The Reconciliation Rule is load-bearing.** When BDD red /
   units green happens, the rule worked: surface the gap, write
   a deeper failing unit test, fix at the right layer. Three
   separate places hit it this session (admin-approve provisioning,
   PostgresEventStore.append on provisioned DBs, Stryker mutant
   activation env) and the discipline held each time.

2. **The §11 loop produces real architectural findings.** Retro #2
   surfaced that §6 Phase 1's catch-all was intent-only; retro #4
   surfaced that the SPA serveStatic path needed a root-route guard;
   retro #5 surfaced the calibration-rule recurrence threshold. The
   retrospectives ARE the audit, not bureaucracy.

3. **Module-identity divergence under ESM + symlinks is a recurring
   trap.** Same `@atlas/identity` imported via package-name vs
   relative path resolves to two URLs = two module instances. Cost
   us debugging time in the BDD setup AND in the Stryker oracle
   wrapper. Worth a future "ESM module identity" finding in
   `docs/incidents/` if it surfaces a fourth time.

4. **Environment-variable leaks across spawn boundaries.** `pnpm safe`
   wrapping, `NODE_TEST_CONTEXT` propagating from parent test runners,
   `__STRYKER_ACTIVE_MUTANT__` needing manual injection — the
   spawning code-paths need explicit env curation, not env inheritance.

5. **Build new substrate via TDD against a reference.** The Stryker
   plugin pattern (build native runner, treat command runner as
   oracle, parity check is the spec) generalizes — anywhere we
   replace a slow-but-correct path with a fast-but-novel one,
   automate parity vs. the old path as a CI gate.
